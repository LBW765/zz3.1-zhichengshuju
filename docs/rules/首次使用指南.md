# 首次使用指南

> 新同事拿到代码后从这里开始，10 分钟跑通环境，按 SOP 开始开发。

---

## 一、项目背景（30 秒读完）

- **项目定位**：国家数字化转型平台（工厂端，覆盖产品 → 生产 → 供应链 → 经营全链路）
- **业务范围**：以 `全软件模块标准报价表V4.5(1)(1).xlsx` 为基线
- **菜单架构**：app-platform 5 个顶级菜单**已锁定，禁止新增**，详见 [菜单规划.md](菜单规划.md)
- **技术栈**：admin（Vue 3 + Element Plus）+ app（uni-app）+ server（Express + MySQL 8）

---

## 二、首次启动 SOP（10 分钟跑通）

### 1. 克隆代码

```bash
git clone https://codeup.aliyun.com/62c54f4c64c8a06be2d68314/zhizhen3.1.git
cd zhizhen3.1
```

### 2. 一键安装 + 启动（推荐）

Windows 直接双击根目录 `一键启动.bat`。脚本只保留一个终端窗口，在其中同时显示后端与管理端日志；后端端口读取 `server/.env` 的 `PORT` 并自动同步前端代理，默认不启动移动端。

```bash
# 首次：安装全部依赖
bash scripts/setup.sh

# 启动后端 + 前端（数据库首次自动初始化）
bash scripts/start.sh
```

脚本会自动检测依赖是否已安装，未安装时先执行 `setup.sh`。

### 2b. 手动安装（备选）

```bash
cd admin && npm install && cd ..
cd app   && npm install && cd ..
cd server && npm install && cd ..
```

### 3. 手动启动（备选，两个终端）

```bash
# 终端 1：后端（端口 3131）
npm run dev:server

# 或启动内存 mock 后端（不连接 MySQL）
npm run dev:server:mock

# 终端 2：后台前端（端口 8131）
npm run dev:admin
```

### 4. 登录验证

打开 http://localhost:8131，使用预设账号登录：

| 账号 | 密码 | 角色 |
|------|------|------|
| administrator | 123456 | 超级管理员 |
| admin | 123456 | 平台管理员 |
| user | 123456 | 普通用户 |

看到工作台和系统管理两个顶级菜单即视为环境正常。

## 三、开始开发（拿到任务后 5 步走）

### Step 1：确认归属

对照 [菜单规划.md](菜单规划.md) 的"归类规则"，确认这个新功能挂在哪个顶级菜单下：
- 工作台 / 产品与营销 / 生产运营 / 供应链与经营 / 系统管理

不确定时按"使用者角色"判断（销售→产品与营销、车间→生产运营、采购财务→供应链与经营、IT→系统管理、全员→工作台）。

### Step 2：找/建业务故事文档

到 [stories/](stories/) 目录找对应业务的故事文档（业务背景、字段、验收标准）：
- 已有故事：直接读，按故事开发
- 没有故事：先和需求方对齐写一份，避免凭空想

### Step 3：按规范开发

最简模块通常涉及 5 处改动：
1. **建表**：`server/db/schema.js` 新增表（基础字段 `id` / `created_by` / `created_at` / `updated_at` 必填）
2. **后端路由**：`server/routes/<模块>.js` 写 CRUD，并在 `server/routes/index.js` 注册
3. **前端 API**：`admin/src/api/<模块>.js` 封装请求
4. **前端页面**：`admin/src/views/<模块>/<页面>/index.vue` 按列表页规范开发
5. **菜单录入**：登录后台 → 系统管理 → 菜单管理 → 在对应顶级菜单下新增二级菜单

详细规范看 [开发规范.md](开发规范.md) 和 [菜单录入规范.md](菜单录入规范.md)。

### Step 4：菜单管理录入命名规则

详见 [菜单录入规范.md](菜单录入规范.md)，重点：
- name 用 PascalCase 且全局唯一
- path 用 kebab-case（顶级带 `/`，二级不带）
- component 路径与 `admin/src/views/` 下实际文件对应
- 列表页 / 详情页 / 编辑页的字段写法各不相同，按规范模板填

### Step 5：本地提交前自查

```bash

# - 是否更新了 README.md（如果改了目录/接口/启动方式）？
# - 是否更新了 docs/开发规范.md（如果改了开发约定）？
# - 是否更新了对应的故事文档（如果字段/流程变了）？
```

## 五、协作硬性约束（红线）

- ❌ **禁止新增顶级菜单**（系统已硬限制 5 个，违反会被拒绝）
- ❌ **禁止跳过菜单归类规则**自行决定挂哪
- ❌ **禁止未读 `开发规范.md`、`菜单规划.md` 就开干**
- ❌ **禁止改端口约定**（后端 3131 / 前端 8131），如必须改请同步更新所有文档
- ✅ 不确定的归类、设计、流程问题 → 先问项目发起人，不要擅自决策
