# 开发规范

## 平台定位（重要）

### app-platform（应用平台）
**定位**：业务功能平台，面向业务操作人员

**包含功能**：
- ✅ 订单管理、商品管理、库存管理、客户管理等业务模块
- ✅ 数据统计、报表分析等业务分析
- ✅ 工作台、消息中心等业务协同

### admin-platform（管理平台）
**定位**：系统管理平台，面向系统管理员

**包含功能**：
- ✅ 平台配置、菜单管理、用户管理、角色管理等系统配置
- ❌ 不要放业务功能（订单、商品、客户等）

### 判断标准
问自己：这个功能是"做业务"还是"管系统"？
- 做业务 → app-platform
- 管系统 → admin-platform

### 硬性约束
- **app-platform**：最多 5 个顶级菜单
- **admin-platform**：固定 1 个顶级菜单（系统管理）

详见：[菜单规划.md](菜单规划.md)

## 权限规范

### 权限码命名规则
格式：`模块:资源:操作`

**标准操作动词**：
- `query` - 查询列表
- `get` - 查看详情
- `add` - 新增
- `edit` - 编辑
- `delete` - 删除
- `export` - 导出
- `import` - 导入

**示例**：
- `order:order:query` - 查询订单列表
- `order:order:add` - 新增订单
- `order:order:export` - 导出订单
- `customer:customer:edit` - 编辑客户

## 代码规范

### 后端规范
- 后端采用模块化架构，所有接口在 `server/routes/` 中按业务模块拆分
- 新增接口步骤：
  1. 在 `server/routes/` 中创建或修改对应模块文件
  2. 在 `server/routes/index.js` 中注册路由（仅新建模块需要）
- 接口路径不带 `/api` 前缀，由 Vite proxy 自动处理
- 数据库表必须包含基础字段：`id`、`created_by`、`created_at`、`updated_at`
- UPDATE 语句时间更新使用 `NOW()`：`` `UPDATE table SET updated_at=NOW() WHERE id=?` ``
- 详见项目 `CLAUDE.md` 的"后端开发规范"章节

## 前端代码规范

### 样式规范

#### 禁止使用 `!important`

```scss
// ❌ 错误
.el-menu-item {
  padding: 0 !important;
}

// ✅ 正确 - 接受组件库默认行为，或通过官方 CSS 变量定制
```

**例外情况**：修复第三方库的已知 bug，需注释说明原因和 issue 链接。

#### 接受组件库默认行为

- Element Plus 等组件库的默认样式已经过设计考量
- 不要为了"看起来更好"而覆盖默认样式
- 如需定制，优先使用官方提供的方式（CSS 变量、主题配置）

#### 避免深层选择器嵌套

```scss
// ❌ 错误 - 嵌套过深
.sidebar {
  .menu {
    .item {
      .icon {
        .svg {
          color: red;
        }
      }
    }
  }
}

// ✅ 正确 - 最多 3 层
.sidebar-menu-item {
  .icon {
    color: red;
  }
}
```

#### `:deep()` 使用原则

- 仅在必要时使用，用于穿透 scoped 样式
- 不要用 `:deep()` 配合 `!important` 强制覆盖

### 组件规范

#### 单一职责

每个组件只做一件事，超过 300 行考虑拆分。

#### Props 定义

```javascript
// ❌ 错误
const props = defineProps(['title', 'visible'])

// ✅ 正确 - 明确类型和默认值
const props = defineProps({
  title: {
    type: String,
    default: ''
  },
  visible: {
    type: Boolean,
    default: false
  }
})
```

### 命名规范

#### 文件命名

- 组件：PascalCase（`UserProfile.vue`）
- 工具/配置：camelCase（`request.js`、`auth.js`）
- 样式：kebab-case（`main-layout.scss`）

#### 变量命名

- 常量：UPPER_SNAKE_CASE（`PLATFORMS`、`ROLES`）
- 变量/函数：camelCase（`currentUser`、`handleLogin`）
- 组件：PascalCase（`SidebarItem`）

### 代码质量

#### 不写无用代码

- 不要留下注释掉的代码
- 不要写"以防万一"的代码
- 删除未使用的导入和变量

#### 保持简洁

```javascript
// ❌ 错误 - 过度防御
if (data && data.user && data.user.name) {
  return data.user.name
}

// ✅ 正确 - 使用可选链
return data?.user?.name
```

#### 注释原则

- 代码应该自解释，减少注释
- 只在"为什么"不明显时添加注释
- 不要用注释解释"是什么"

## 列表页开发规范（重要）

### 标准列表页结构（必须遵循）

所有列表页必须按以下结构开发，**开发前必须参考样板页**。

#### 1. PageHeader 操作按钮

```vue
<PageHeader title="页面标题" description="页面描述" class="page-shell__section">
  <template #extra>
    <el-button :icon="Refresh" @click="fetchList">刷新</el-button>
    <el-button type="primary" :icon="Plus" @click="handleAdd">新增XXX</el-button>
  </template>
</PageHeader>
```

**规范要点**：
- 必须包含"刷新"按钮（`:icon="Refresh"` + `@click="fetchList"`）
- 主要操作按钮（如"新增"）使用 `type="primary"` + 对应图标
- 按钮顺序：刷新在前，主要操作在后
- 需要导入图标：`import { Refresh, Plus } from '@element-plus/icons-vue'`

#### 2. 完整页面结构

```vue
<template>
  <div class="page-shell">
    <!-- 1. 页面头部 -->
    <PageHeader title="XXX管理" description="管理XXX信息" class="page-shell__section">
      <template #extra>
        <el-button :icon="Refresh" @click="fetchList">刷新</el-button>
        <el-button type="primary" :icon="Plus" @click="handleAdd">新增XXX</el-button>
      </template>
    </PageHeader>

    <!-- 2. 搜索工具栏（可选）：筛选项放 __filters，按钮放 __actions，左右两组各自紧凑 -->
    <el-card shadow="never" class="toolbar-card page-card page-shell__section page-toolbar">
      <div class="toolbar-row page-toolbar__row">
        <div class="page-toolbar__filters">
          <el-input v-model="searchKeyword" placeholder="搜索..." clearable :prefix-icon="Search" style="width: 300px" @keyup.enter="handleSearch" />
          <el-select v-model="statusFilter" placeholder="状态" clearable style="width: 120px">
            <el-option label="启用" :value="1" />
            <el-option label="禁用" :value="0" />
          </el-select>
        </div>
        <div class="page-toolbar__actions">
          <el-button type="primary" :icon="Search" @click="handleSearch">搜索</el-button>
          <el-button :icon="Refresh" @click="resetSearch">重置</el-button>
        </div>
      </div>
    </el-card>

    <!-- 3. 表格 -->
    <el-card shadow="never" class="page-card page-shell__section table-page-card">
      <div class="table-shell">
        <el-table :data="tableData" v-loading="loading" stripe :fit="false">
          <el-table-column prop="name" label="名称" min-width="200" show-overflow-tooltip />
          <!-- 更多列 -->
          <el-table-column label="操作" width="160" fixed="right" align="left">
            <template #default="{ row }">
              <div class="table-actions">
                <el-button type="primary" link @click="handleEdit(row)">编辑</el-button>
                <el-button type="danger" link @click="handleDelete(row)">删除</el-button>
              </div>
            </template>
          </el-table-column>
        </el-table>
      </div>
      <div class="pagination-wrapper">
        <el-pagination v-model:current-page="currentPage" v-model:page-size="pageSize" :page-sizes="[10, 20, 50]" :total="total" layout="total, sizes, prev, pager, next, jumper" @size-change="handleSizeChange" @current-change="handlePageChange" />
      </div>
    </el-card>
  </div>
</template>
```

#### 3. 样板页参考（必读）

**开发新列表页前必须先阅读以下样板页，确保结构一致**：

- 用户管理：`admin/src/views/system/user/index.vue`
- 角色管理：`admin/src/views/system/role/index.vue`
- 菜单管理：`admin/src/views/system/menu/index.vue`

#### 4. 搜索工具栏排版规则（重要）

- 工具栏 `page-toolbar__row` 内部**必须分两组**：左侧筛选用 `page-toolbar__filters` 包，右侧操作按钮用 `page-toolbar__actions` 包
- 全局规则会让 `__filters` 占据剩余空间紧凑左排，`__actions` 紧贴右侧紧凑成组
- **禁止**把 `el-input` / `el-select` / `el-button` 直接平铺为 `__row` 的子元素 — 这会触发 `space-between` 把所有元素均匀撑开，造成异常间距
- 单个搜索框场景可直接使用 `page-toolbar__search` 类，不需要包 `__filters`

#### 5. 常见错误

❌ **错误示例**：
```vue
<!-- 错误1：没有刷新按钮 -->
<PageHeader title="部门管理">
  <template #extra>
    <el-button type="primary" @click="handleAdd">新增部门</el-button>
  </template>
</PageHeader>

<!-- 错误2：按钮没有图标 -->
<el-button @click="fetchList">刷新</el-button>

<!-- 错误3：按钮顺序错误 -->
<template #extra>
  <el-button type="primary" :icon="Plus" @click="handleAdd">新增</el-button>
  <el-button :icon="Refresh" @click="fetchList">刷新</el-button>
</template>

<!-- 错误4：工具栏筛选项未分组，直接平铺导致 space-between 异常间距 -->
<div class="page-toolbar__row">
  <el-input ... />
  <el-select ... />
  <el-button>搜索</el-button>
  <el-button>重置</el-button>
</div>
```

## 主题色规范

### 核心变量

所有主题色通过 CSS 变量控制，统一在 `:root` 中定义：

```scss
:root {
  --primary-color: #409EFF;        // 主题色
  --primary-light: #66b1ff;        // 主题色-浅
  --primary-dark: #337ecc;         // 主题色-深
}
```

### 使用场景

#### 必须使用主题色的场景

| 场景 | 实现方式 | 示例 |
|------|----------|------|
| 主按钮 | `type="primary"` | 提交、确认、保存 |
| 页面标题头 | 使用 `PageHeader` 组件 | 所有内容页面 |
| 选中/激活状态 | `color: var(--primary-color)` | 菜单选中、Tab 激活 |
| 链接文字 | `color: var(--primary-color)` | 可点击的文字 |
| 开关/进度条 | Element Plus 默认 | 开启状态 |
| 图标高亮 | `color: var(--primary-color)` | 当前选中的图标 |

#### 禁止硬编码颜色

```scss
// ❌ 错误 - 硬编码颜色值
.active {
  color: #409EFF;
  background: rgba(64, 158, 255, 0.1);
}

// ✅ 正确 - 使用 CSS 变量
.active {
  color: var(--primary-color);
  background: rgba(var(--primary-color-rgb), 0.1);
}
```

### 页面标题头规范

所有内容页面必须使用统一的 `PageHeader` 组件：

```vue
<template>
  <div class="page-shell">
    <PageHeader
      title="页面标题"
      description="页面描述信息"
      class="page-shell__section"
    />
    <!-- 页面内容 -->
  </div>
</template>
```

#### PageHeader 样式标准

- 背景：主题色渐变 `linear-gradient(135deg, var(--primary-color), var(--primary-light))`
- 文字：白色
- 圆角：12px
- 内边距：24px 28px

### 按钮颜色规范

| 按钮类型 | 使用场景 |
|----------|----------|
| Primary（主题色） | 主要操作：提交、保存、确认 |
| Default（默认） | 次要操作：取消、返回 |
| Success（绿色） | 成功操作：通过、完成 |
| Warning（橙色） | 警告操作：提醒、注意 |
| Danger（红色） | 危险操作：删除、禁用 |
| Info（灰色） | 信息操作：查看、详情 |

### 状态颜色规范

| 状态 | 颜色 | 使用场景 |
|------|------|----------|
| 主要/激活 | `--primary-color` | 选中、当前、激活 |
| 成功 | `--success-color` | 成功、通过、在线 |
| 警告 | `--warning-color` | 警告、待处理 |
| 错误 | `--danger-color` | 错误、失败、离线 |
| 信息 | `--info-color` | 普通信息、禁用 |

### 修改主题色

用户可在「平台配置」中修改主题色，系统自动更新所有使用 `var(--primary-color)` 的地方。

**注意**：如果硬编码了 `#409EFF`，则不会随主题色变化，这是不规范的写法。

## 弹窗与抽屉规范

### 基本原则

#### 简洁清晰
- 标题直接表达意图，不添加装饰性图标
- 内容区域使用 `el-form` 保持统一布局
- 避免过度装饰，保持专业简洁

#### 功能明确
- 弹窗(Dialog)：用于需要用户关注的操作，如确认、表单提交
- 抽屉(Drawer)：用于详情展示、设置面板、操作日志等

### 弹窗(Dialog)规范

#### 基础用法

```vue
<el-dialog v-model="visible" title="标题" width="500px">
  <el-form label-width="80px">
    <el-form-item label="字段名">
      <span>字段值</span>
    </el-form-item>
  </el-form>
  <template #footer>
    <el-button @click="visible = false">关 闭</el-button>
  </template>
</el-dialog>
```

#### 弹窗类型与宽度

| 类型 | 宽度 | 用途 |
|------|------|------|
| 确认弹窗 | 420px | 简单确认、删除提示 |
| 信息展示 | 500px | 详情查看、消息展示 |
| 表单弹窗 | 520px | 新增、编辑表单 |
| 复杂表单 | 640px | 多字段表单、带表格 |

#### 标题规范

```vue
<!-- ✅ 正确 - 简洁明了 -->
<el-dialog title="消息详情">
<el-dialog title="删除确认">
<el-dialog title="新增用户">

<!-- ❌ 错误 - 不要添加装饰图标 -->
<el-dialog title="📝 消息详情">
<el-dialog>
  <template #header>
    <el-icon><Warning /></el-icon> 删除确认
  </template>
</el-dialog>
```

#### 内容区域布局

使用 `el-form` 统一布局，即使只是展示信息：

```vue
<!-- ✅ 正确 - 使用 el-form 布局 -->
<el-dialog title="用户详情" width="500px">
  <el-form label-width="80px">
    <el-form-item label="用户名">
      <span>张三</span>
    </el-form-item>
    <el-form-item label="邮箱">
      <span>zhangsan@example.com</span>
    </el-form-item>
    <el-form-item label="状态">
      <el-tag type="success" size="small">正常</el-tag>
    </el-form-item>
  </el-form>
</el-dialog>

<!-- ❌ 错误 - 自定义布局不统一 -->
<el-dialog title="用户详情">
  <div class="custom-layout">
    <div class="label">用户名：</div>
    <div class="value">张三</div>
  </div>
</el-dialog>
```

#### 底部按钮规范

```vue
<!-- 信息展示型 - 只有关闭按钮 -->
<template #footer>
  <el-button @click="visible = false">关 闭</el-button>
</template>

<!-- 确认操作型 - 取消 + 确定 -->
<template #footer>
  <el-button @click="visible = false">取 消</el-button>
  <el-button type="primary" @click="handleSubmit">确 定</el-button>
</template>

<!-- 危险操作型 - 取消 + 危险按钮 -->
<template #footer>
  <el-button @click="visible = false">取 消</el-button>
  <el-button type="danger" @click="handleDelete">确 定</el-button>
</template>
```

**按钮文字规范**：
- 使用空格分隔：`关 闭`、`取 消`、`确 定`、`保 存`
- 操作按钮在右侧
- 取消/关闭按钮在左侧

#### 确认弹窗

简单确认推荐使用 `ElMessageBox`：

```javascript
import { ElMessageBox, ElMessage } from 'element-plus'

ElMessageBox.confirm('确定要删除这条记录吗？', '删除确认', {
  confirmButtonText: '确定',
  cancelButtonText: '取消',
  type: 'warning'
}).then(() => {
  ElMessage.success('删除成功')
}).catch(() => {})
```

### 抽屉(Drawer)规范

#### 基础用法

```vue
<el-drawer v-model="visible" title="标题" size="480px">
  <el-form label-width="80px">
    <!-- 内容 -->
  </el-form>
  <template #footer>
    <el-button @click="visible = false">关 闭</el-button>
    <el-button type="primary">操 作</el-button>
  </template>
</el-drawer>
```

#### 抽屉方向与尺寸

| 方向 | 属性 | 推荐尺寸 | 用途 |
|------|------|----------|------|
| 右侧 | 默认 | 400-500px | 详情展示、编辑表单 |
| 左侧 | `direction="ltr"` | 360-400px | 设置面板、筛选器 |
| 底部 | `direction="btt"` | 280-360px | 操作日志、批量操作 |

### 禁止事项

#### 不要添加装饰性内容

```vue
<!-- ❌ 错误 - 不要使用装饰性图标和自定义样式 -->
<el-dialog>
  <div class="dialog-header">
    <el-icon><InfoFilled /></el-icon>
    <h3>消息详情</h3>
  </div>
  <div class="dialog-content">
    <div class="content-item">
      <span class="label">标题：</span>
      <span class="value">系统通知</span>
    </div>
  </div>
</el-dialog>
```

#### 不要过度设计

```scss
// ❌ 错误 - 不要添加多余的样式
.dialog-content {
  background: linear-gradient(135deg, #f5f7fa 0%, #e4e7ed 100%);
  border-radius: 12px;
  padding: 24px;
  box-shadow: inset 0 2px 8px rgba(0, 0, 0, 0.1);
}
```

#### 不要使用内联样式

```vue
<!-- ❌ 错误 -->
<el-form-item label="状态">
  <span style="color: green; font-weight: bold;">正常</span>
</el-form-item>

<!-- ✅ 正确 - 使用组件 -->
<el-form-item label="状态">
  <el-tag type="success" size="small">正常</el-tag>
</el-form-item>
```

### label-width 规范

| 场景 | label-width | 说明 |
|------|-------------|------|
| 常规表单 | 80px | 2-4个中文字 |
| 长标签 | 100px | 4-5个中文字 |
| 超长标签 | 120px | 5个以上中文字 |

**原则**：同一弹窗/抽屉内使用统一的 label-width。

### 全局样式（已配置）

以下样式已在 `admin/src/assets/styles/element-plus.scss` 中全局配置，无需手动添加。

**所有 Element Plus 组件的样式覆盖必须统一在 `element-plus.scss` 中修改，禁止在业务页面中重复覆盖。**

```scss
// ❌ 禁止 - 在页面中单独覆盖
// src/views/xxx/index.vue
<style scoped>
.el-dialog__header {
  border-bottom: 1px solid #eee;
}
</style>

// ✅ 正确 - 统一在全局文件中修改
// src/assets/styles/element-plus.scss
.el-dialog__header {
  border-bottom: 1px solid var(--border-color);
}
```

**原因**：
- 避免样式分散，难以维护
- 保证全项目一致性
- 后续优化只需改一处

## 数据库表设计规范（重要）

### 基础字段（必填）

所有业务表必须包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT AUTO_INCREMENT PRIMARY KEY | 主键 |
| `created_by` | INT | 创建人ID（关联 users 表） |
| `created_at` | DATETIME DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME DEFAULT CURRENT_TIMESTAMP | 更新时间 |

### 可选字段（根据业务需要）

| 字段 | 类型 | 说明 |
|------|------|------|
| `updated_by` | INT | 更新人ID |
| `deleted_at` | DATETIME | 软删除时间（如果需要软删除） |
| `status` | INT | 状态字段（如果有状态流转） |

### 业务编号字段规范（重要）

凡有业务编号的表，必须遵循以下规范：

#### 1. 字段命名
- 统一命名为 `xxx_no`（如 `customer_no`、`order_no`、`contract_no`）
- 必须建唯一索引：`UNIQUE(xxx_no)`

#### 2. 编号生成
- **必须接入编码规则服务**（`server/services/codeGenerator.js`）
- **禁止在业务代码中拼接字符串**生成编号
- **并发安全**：服务内部使用数据库事务保证并发取号不重复

#### 3. 使用方式

**后端接口中使用**：
```javascript
const { generateCode } = require('../services/codeGenerator')

// 创建订单时生成订单号
router.post('/', authMiddleware, async (req, res) => {
  try {
    const orderNo = await generateCode('ORDER', req.user.id)

    const { insertId } = await db.run(
      'INSERT INTO orders (order_no, customer_id, amount, created_by) VALUES (?, ?, ?, ?)',
      [orderNo, req.body.customer_id, req.body.amount, req.user.id]
    )

    res.json({ code: 200, data: { id: insertId, order_no: orderNo } })
  } catch (error) {
    res.status(500).json({ code: 500, message: error.message })
  }
})
```

## 数据库迁移规范（重要）

### 核心原则

**每次提交代码前，必须汇总本次变更的所有数据库影响，生成一份完整的迁移脚本。**

### 什么情况需要创建迁移脚本

只要涉及以下任何一项，都必须创建迁移脚本：

- ✅ 新增数据表
- ✅ 修改表结构（新增字段、修改字段类型、删除字段）
- ✅ 新增菜单数据
- ✅ 新增演示数据（如果预生产环境需要）
- ✅ 修改配置数据
- ✅ 新增索引或约束

### 迁移脚本命名规范

```
server/db/migrations/YYYYMMDD_功能描述.js
```

**示例**：
- `20260430_add_code_rule_module.js` - 新增编码规则管理模块
- `20260501_add_customer_fields.js` - 客户表新增字段
- `20260502_add_order_menu.js` - 新增订单管理菜单

### 迁移脚本结构（必须遵循）

```javascript
/**
 * 数据库迁移：功能描述
 * 执行时间：YYYY-MM-DD
 *
 * 变更内容：
 * 1. 新增表：xxx, yyy
 * 2. 修改表：zzz（新增字段 aaa, bbb）
 * 3. 新增菜单：xxx管理
 * 4. 新增演示数据：xxx规则
 */

const mysql = require('mysql2/promise')
require('dotenv').config({ path: require('path').join(__dirname, '../.env') })

async function migrate() {
  const pool = await mysql.createPool({
    host: process.env.DB_HOST,
    port: Number(process.env.DB_PORT) || 3306,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    database: process.env.DB_NAME,
    charset: 'utf8mb4'
  })

  console.log('🚀 开始执行迁移：功能描述')

  const conn = await pool.getConnection()
  try {
    await conn.beginTransaction()

    // ========== 1. 表结构变更 ==========
    const [tables] = await conn.query(
      "SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ?",
      [process.env.DB_NAME, 'xxx']
    )

    if (tables.length) {
      console.log('⏭️  xxx 表已存在，跳过创建')
    } else {
      await conn.query(`CREATE TABLE IF NOT EXISTS xxx (...) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`)
      console.log('✅ 创建 xxx 表')
    }

    // ========== 2. 菜单数据 ==========
    const [menuRows] = await conn.query('SELECT id FROM menus WHERE id = ?', [菜单ID])

    if (menuRows.length) {
      console.log('⏭️  xxx菜单已存在，跳过创建')
    } else {
      await conn.query('INSERT INTO menus (...) VALUES (...)', [...])
      console.log('✅ 新增 xxx 菜单')
    }

    // ========== 3. 演示数据 ==========
    const [countRows] = await conn.query('SELECT COUNT(*) as count FROM xxx')

    if (countRows[0].count > 0) {
      console.log('⏭️  xxx演示数据已存在，跳过插入')
    } else {
      // 插入演示数据
      console.log('✅ 新增 xxx 演示数据')
    }

    await conn.commit()
    console.log('✅ 迁移成功完成')

  } catch (error) {
    await conn.rollback()
    console.error('❌ 迁移失败，已回滚:', error.message)
    throw error
  } finally {
    conn.release()
    await pool.end()
  }
}

if (require.main === module) {
  migrate()
}

module.exports = migrate
```

### 迁移脚本要求

#### 1. 必须幂等
- 可以重复执行，不会报错
- 使用 `IF NOT EXISTS` 或先检查再创建

#### 2. 必须有事务保护
- 使用 `BEGIN TRANSACTION` 和 `COMMIT`
- 失败时自动 `ROLLBACK`

#### 3. 必须有清晰的日志
- 使用统一的 emoji 标识：
  - 📦 数据库路径
  - 🚀 开始执行
  - ⏭️  跳过（已存在）
  - ✅ 成功
  - ❌ 失败

#### 4. 必须支持命令行参数
```javascript
const dbPath = process.argv[2] || process.env.DB_PATH || path.join(__dirname, '../data.db')
```

### 常见错误

#### ❌ 错误 1：只提交代码，不提交迁移脚本
```
开发者A：本地开发完成，提交代码
预生产环境：拉取代码后，数据库没有新表/新菜单，功能报错
```

#### ❌ 错误 2：手动在预生产执行 SQL，不记录迁移脚本
```
开发者A：SSH 登录服务器，手动执行 SQL
开发者B：拉取代码后，不知道要执行什么 SQL，功能报错
```

#### ❌ 错误 3：迁移脚本不幂等，重复执行报错
```sql
-- 错误示例
CREATE TABLE xxx (...);  -- 第二次执行会报错：表已存在

-- 正确示例
CREATE TABLE IF NOT EXISTS xxx (...);
-- 或者先检查再创建
```

#### ❌ 错误 4：迁移脚本没有事务保护
```javascript
// 错误示例
db.exec(`CREATE TABLE xxx (...)`)
db.exec(`CREATE TABLE yyy (...)`)  // 如果这里失败，xxx 表已经创建了

// 正确示例
db.exec('BEGIN TRANSACTION')
try {
  db.exec(`CREATE TABLE xxx (...)`)
  db.exec(`CREATE TABLE yyy (...)`)
  db.exec('COMMIT')
} catch (error) {
  db.exec('ROLLBACK')
  throw error
}
```
