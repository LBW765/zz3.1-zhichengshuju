# 导入导出设计规范

> 本规范用于统一系统内所有批量导入、批量导出能力，优先适用于基础数据，后续采购、销售、仓储、售后、人力资源等模块的导入导出功能也按本规范实现。
>
> 目标：导入时让用户先下载模板、上传预览并修正问题，最后再写入数据库；导出时让用户能选择导出范围、选择导出字段，并直接下载 Excel。开发同事按同一套字段、接口、校验和结果格式实现，避免每个模块体验不一致。

---

## 一、适用范围

### 1.1 首批适用对象

基础数据模块优先统一：

- 计量单位、单位组
- 物料分类、物料档案
- 工序、工艺路线、BOM
- 车间、产线、班组
- 供应商分类、供应商档案
- 客户分类、客户档案
- 仓库、库区、库位
- 设备分类、设备档案
- 服务商分类、服务商档案

### 1.2 后续适用对象

后续业务模块只要存在批量导入，也应复用同一套导入流程：

- 采购：供应商报价、采购计划、采购订单明细等
- 销售：客户池、商机、报价单、销售订单明细等
- 仓储：库存初始数据、盘点明细等
- 售后：历史售后工单、客户设备台账等
- 人力资源：员工档案、考勤记录、薪资档案等

---

## 二、标准流程

所有导入功能必须分三步，不允许上传后直接写库。

### 2.1 第一步：下载模板与上传文件

用户点击“导入”后打开导入弹窗，第一步展示：

- “下载导入模板”按钮
- 文件上传区域
- 支持格式说明
- 模板填写说明

模板必须明确：

- 哪些字段必填
- 哪些字段非必填
- 每个字段的示例值
- 字段取值范围或填写规则
- 关联字段的填写方式，例如“填写供应商编码”“填写分类名称”

交互要求：

- 只支持 `.xlsx`，可兼容 `.xls`
- 单次只允许上传一个文件
- 文件为空、格式错误、没有数据行时，进入预览页并显示错误
- 示例行允许保留作为模板示例，但正式导入时推荐用户删除；如保留，系统应能通过字段配置识别并过滤示例行

### 2.2 第二步：导入预览与前置校验

上传文件后不直接入库，先解析 Excel 并展示预览表格。

预览页必须展示：

- 总行数
- 校验通过行数
- 校验失败行数
- 数据表格预览
- 错误字段标红
- 错误原因提示

预览阶段必须做前端可判断的校验：

- 必填字段不能为空
- 数字字段格式正确
- 日期字段格式正确
- 枚举字段在允许范围内
- 手机号、邮箱、税号等常见格式校验
- 同一个文件内唯一字段不能重复，例如编码、名称等
- 关联字段格式完整，例如“分类编码”“单位符号”

预览阶段建议支持用户直接在表格里修正单元格。修正后实时重新校验。

如果存在预览错误：

- “下一步/开始导入”按钮禁用
- 用户可以在页面中修正
- 或重新上传修正后的 Excel

### 2.3 第三步：正式写入与导入结果

只有预览阶段校验通过后，才能执行正式导入。

正式导入时后端必须再次校验，不能只相信前端校验结果。

后端写入时必须判断：

- 数据库中唯一字段是否重复
- 关联数据是否存在
- 业务状态是否允许导入
- 编码规则是否允许外部编码或需要自动生成
- 数值范围是否符合业务约束
- 当前用户是否有导入权限

导入完成后展示结果：

- 总行数
- 成功行数
- 失败行数
- 失败明细表格
- 下载失败结果按钮

失败明细必须包含：

- Excel 原始行号
- 业务主键字段，例如编码、名称
- 失败字段
- 失败原因
- 原始行数据

支持下载失败结果 Excel，用户修改后可重新导入。

## 三、模板规范

### 3.1 模板文件命名

格式：

```text
<业务名称>导入模板.xlsx
```

示例：

- `物料档案导入模板.xlsx`
- `供应商档案导入模板.xlsx`
- `仓库导入模板.xlsx`
- `员工档案导入模板.xlsx`

### 3.2 Sheet 命名

默认：

```text
导入模板
```

如一个模板包含多个 Sheet，必须按业务对象命名：

- `物料档案`
- `BOM主表`
- `BOM明细`
- `填写说明`

### 3.3 表头规范

表头必须使用中文业务名称，不直接暴露数据库字段名。

必填字段表头统一标注：

```text
物料编码（必填）
```

非必填字段不加“非必填”字样。

有关联、枚举、格式要求的字段，必须在备注或说明行中标清：

```text
物料类型（必填）
原材料/半成品/成品/辅料
```

### 3.4 示例行

模板必须提供至少一行示例数据。

示例行要求：

- 必填字段都要有值
- 示例值要接近真实业务
- 编码示例要符合当前编码习惯
- 枚举字段必须使用系统允许值

示例：

| 物料编码（必填） | 物料名称（必填） | 物料分类（必填） | 计量单位（必填） | 保质期天数 |
|---|---|---|---|---|
| WL-00001 | 铝合金板材 | 原材料 | kg | 365 |

### 3.5 字段配置标准

前端导入字段统一使用 `columns` 配置，字段结构如下：

```js
{
  key: 'materialCode',
  label: '物料编码',
  required: true,
  example: 'WL-00001',
  width: 16,
  note: '唯一，不允许重复',
  type: 'string',
  unique: true,
  enum: [],
  maxLength: 50
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `key` | 是 | 前端提交给后端的字段名，使用 camelCase |
| `label` | 是 | Excel 表头中文名称 |
| `required` | 否 | 是否必填 |
| `example` | 否 | 模板示例值 |
| `width` | 否 | Excel 列宽 |
| `note` | 否 | 模板填写说明 |
| `type` | 否 | `string` / `number` / `date` / `enum` / `boolean` |
| `unique` | 否 | 是否在文件内要求唯一 |
| `enum` | 否 | 枚举可选值 |
| `maxLength` | 否 | 最大长度 |
| `validate` | 否 | 自定义前端校验函数 |

## 四、前端交互规范

### 4.1 导入入口按钮

导入按钮放在列表页工具栏中，与导出、新增同一层级。

推荐顺序：

```text
刷新 / 导入 / 导出 / 新增
```

导入按钮图标使用 `Upload`。

### 4.2 导入弹窗形态

导入统一使用弹窗，不新开页面。

弹窗推荐宽度：

- 小字段导入：`720px`
- 需要预览表格：`960px`
- 字段很多或可编辑预览：`80vw`

弹窗顶部必须展示步骤条：

```text
1 下载模板/上传文件 → 2 预览校验 → 3 导入结果
```

### 4.3 预览表格

预览表格要求：

- 固定显示 Excel 原始行号
- 必填缺失字段标红
- 格式错误字段标红
- 鼠标悬停或单元格下方显示错误原因
- 错误行支持筛选
- 支持只看错误数据

建议字段：

| 列 | 说明 |
|---|---|
| 行号 | Excel 原始行号 |
| 状态 | 正常 / 错误 |
| 错误说明 | 汇总本行错误 |
| 业务字段 | 按模板字段展示 |

### 4.4 用户修正方式

标准支持两种修正方式：

1. 页面内直接编辑预览表格，实时校验
2. 下载错误结果，在线下 Excel 修改后重新上传

第一版如果不做表格内编辑，必须至少支持：

- 清晰展示错误位置
- 下载错误结果
- 重新上传

### 4.5 结果页

结果页必须包含：

- 成功/失败/部分成功状态
- 统计数字
- 错误明细
- 下载错误结果
- 重新上传
- 关闭

结果页不允许只弹一个 toast 后关闭。

## 五、导出交互规范

### 5.1 导出入口按钮

导出按钮放在列表页工具栏中，与导入、新增同一层级。

推荐顺序：

```text
刷新 / 导入 / 导出 / 新增
```

导出按钮图标使用 `Download`。

如果当前用户没有导出权限，前端隐藏导出按钮，后端接口也必须拦截。

### 5.2 列表勾选能力

所有支持导出的标准列表页，表格第一列必须支持勾选。

勾选能力至少包括：

- 勾选单行
- 当前页全选
- 清空选择
- 跨页保留已选数据

如果业务数据量较大，必须额外支持“选择全部符合筛选条件的数据”，不能只导出当前页。

### 5.3 导出范围

点击导出后打开导出弹窗或下拉菜单，用户必须能选择导出范围。

标准范围：

| 导出范围 | 说明 |
|---|---|
| 导出已勾选数据 | 只导出当前勾选的记录 |
| 导出当前页数据 | 导出当前分页表格里的记录 |
| 导出全部筛选结果 | 按当前搜索条件导出所有符合条件的数据 |

默认推荐：

- 如果用户已经勾选数据，默认选择“导出已勾选数据”
- 如果没有勾选数据，默认选择“导出全部筛选结果”

导出全部筛选结果时，必须沿用当前列表页的筛选条件，例如关键字、分类、状态、日期范围等。

### 5.4 导出字段选择

导出前必须支持选择字段。

场景示例：

> 列表数据有 10 个字段，用户只想导出其中 5 个字段。导出弹窗中应展示字段勾选项，用户勾选 5 个字段后再导出。

字段选择要求：

- 默认勾选常用字段
- 支持全选字段
- 支持清空后重新选择
- 至少选择 1 个字段才能导出
- 字段顺序默认按列表/业务字段顺序输出
- 后续可扩展拖拽排序，但第一版不强制

字段选项必须使用中文业务名称，不展示数据库字段名。

示例：

| 字段编码 | 字段名称 | 默认导出 |
|---|---|---:|
| `materialCode` | 物料编码 | 是 |
| `materialName` | 物料名称 | 是 |
| `categoryName` | 物料分类 | 是 |
| `spec` | 规格型号 | 是 |
| `remark` | 备注 | 否 |

### 5.5 导出弹窗

导出弹窗建议包含三块：

- 导出范围
- 导出字段
- 导出说明

弹窗底部按钮：

```text
取消 / 确认导出
```

确认导出后：

- 前端显示 loading
- 后端生成 Excel
- 浏览器直接下载文件
- 导出完成后关闭 loading

导出成功不需要跳转页面。

### 5.6 导出文件命名

导出文件命名格式：

```text
<业务名称>_<导出日期时间>.xlsx
```

示例：

- `物料档案_20260601153000.xlsx`
- `供应商档案_20260601153000.xlsx`
- `销售订单_20260601153000.xlsx`

如果是错误结果导出，命名格式：

```text
<业务名称>导入失败结果_<导出日期时间>.xlsx
```

### 5.7 导出数据口径

导出必须遵循“用户看到什么口径，就导出什么口径”。

要求：

- 列表页筛选条件要完整传给后端
- 枚举值导出中文名称，不导出内部编码
- 关联字段导出业务名称或编码，例如供应商名称、物料编码
- 金额、数量、日期按页面展示口径格式化
- 敏感字段按权限控制，没权限不能导出明文

敏感字段示例：

- 身份证号
- 银行卡号
- 手机号
- 财务账号
- 采购/销售价格

### 5.8 大数据量导出

第一版可同步导出，但必须设置合理上限。

建议：

- 前端一次导出超过 5000 行时提示用户确认
- 后端同步导出建议限制在 20000 行以内
- 超过上限后，后续扩展为异步导出任务

异步导出任务后续可扩展：

- 创建导出任务
- 后台生成文件
- 消息通知
- 用户到导出记录中下载

## 六、后端接口规范

### 6.1 导入推荐接口

每个支持导入的资源建议提供三个接口：

```text
GET  /<module>/<resource>/import-template
POST /<module>/<resource>/import/preview
POST /<module>/<resource>/import/commit
```

说明：

| 接口 | 用途 |
|---|---|
| `import-template` | 下载模板。可由前端生成时省略，但字段标准仍以后端/文档为准 |
| `import/preview` | 服务端预校验，返回预览错误，不写库 |
| `import/commit` | 正式写入数据库，返回成功失败明细 |

### 6.2 导入兼容现有接口

当前项目中已有不少接口使用：

```text
POST /<module>/<resource>/import
```

这个接口可以暂时保留，但新开发功能必须逐步迁移到：

```text
POST /<module>/<resource>/import/preview
POST /<module>/<resource>/import/commit
```

如果短期只实现一个 `import` 接口，也必须满足：

- 前端先做本地预览校验
- 后端返回逐行结果
- 不允许遇到第一条错误就整体中断

### 6.3 导入请求格式

预览接口推荐传结构化 JSON：

```json
{
  "fileName": "物料档案导入.xlsx",
  "rows": [
    {
      "__rowNo": 2,
      "materialCode": "WL-00001",
      "materialName": "铝合金板材"
    }
  ]
}
```

字段要求：

- `__rowNo` 必须保留 Excel 原始行号
- 业务字段使用 camelCase
- 空字符串统一传 `''`，不要传 `undefined`

如果后端直接接收文件，使用 `multipart/form-data`，字段名统一为：

```text
file
```

### 6.4 导入响应格式

预览响应：

```json
{
  "code": 200,
  "message": "校验完成",
  "data": {
    "total": 100,
    "valid": 96,
    "invalid": 4,
    "rows": [],
    "errors": [
      {
        "row": 3,
        "field": "materialCode",
        "label": "物料编码",
        "value": "",
        "message": "物料编码不能为空"
      }
    ]
  }
}
```

提交响应：

```json
{
  "code": 200,
  "message": "导入完成",
  "data": {
    "total": 100,
    "success": 95,
    "failed": 5,
    "errors": [
      {
        "row": 12,
        "field": "materialCode",
        "label": "物料编码",
        "value": "WL-00001",
        "message": "物料编码已存在"
      }
    ]
  }
}
```

### 6.5 导出推荐接口

每个支持导出的资源建议提供一个接口：

```text
POST /<module>/<resource>/export
```

导出接口必须返回 Excel 文件流。

前端请求时应设置 `responseType: 'blob'`，拿到响应后直接触发浏览器下载。

### 6.6 导出请求格式

导出请求统一传：

```json
{
  "scope": "selected",
  "ids": [1, 2, 3],
  "filters": {
    "keyword": "铝合金",
    "status": 1
  },
  "fields": ["materialCode", "materialName", "categoryName", "spec"]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `scope` | 是 | `selected` / `currentPage` / `allFiltered` |
| `ids` | 否 | 已勾选记录 ID，`selected` 时必填 |
| `filters` | 否 | 当前列表筛选条件，`allFiltered` 时必须完整传入 |
| `fields` | 是 | 用户勾选的导出字段，至少 1 个 |

`scope` 取值说明：

| 值 | 说明 |
|---|---|
| `selected` | 导出已勾选数据 |
| `currentPage` | 导出当前页数据 |
| `allFiltered` | 导出全部筛选结果 |

### 6.7 导出响应格式

成功时直接返回 Excel 文件流。

响应头建议：

```text
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="<encoded-file-name>.xlsx"
```

失败时返回 JSON：

```json
{
  "code": 400,
  "message": "请选择至少一个导出字段"
}
```

前端需要兼容 blob 错误响应，解析失败原因并提示用户。

### 6.8 后端事务策略

导入事务策略由业务决定，但必须在界面上明确。

推荐默认策略：

- 基础数据导入：允许部分成功
- 强一致业务单据导入：整单失败回滚

允许部分成功时：

- 每行独立校验和写入
- 成功行提交
- 失败行返回错误明细

整单回滚时：

- 只要任意一行失败，全部不写入
- 返回所有可识别错误
- 响应里 `success = 0`

## 七、校验规范

### 7.1 导入前端校验

前端负责快速发现明显问题：

- 必填为空
- 类型不正确
- 日期格式不正确
- 枚举值不正确
- 文件内重复
- 长度超限

前端校验通过不代表一定能入库。

### 7.2 导入后端校验

后端必须重复执行关键校验：

- 权限校验
- 必填校验
- 类型校验
- 唯一性校验
- 数据库重复校验
- 关联存在性校验
- 状态合法性校验
- 业务规则校验

后端不能因为前端已经校验就省略校验。

### 7.3 导出校验

导出前后端都必须校验：

- 是否选择了导出范围
- `selected` 范围下是否存在已勾选数据
- 是否至少选择一个导出字段
- 字段是否在白名单内
- 当前用户是否有字段查看权限
- 当前用户是否有导出权限
- 导出数据量是否超过上限

## 附录 A：后端导出实现指南（防 OOM）

> 第五章/第六章定义了"业务规范",本附录定义"代码必须怎么写才能不爆"。
> 凡是后端写导出接口,**强制阅读本附录**。

### A.1 历史教训

历史上踩过的坑:50 万行报工导出,后端 Node 进程 OOM 直接挂掉,被迫同步数据到 ES 才"绕过"问题。

**真正原因不是数据库扛不住,是导出代码写错了**:
- `stmt.all()` 一次性把结果集全拉进内存
- `new ExcelJS.Workbook()` 默认非流式,整张表在内存里建好再序列化
- 50 万条 × 单条 300~500 字节 × ExcelJS 对象膨胀 5~10 倍 ≈ **1~2 GB 堆内存** → 必 OOM

正确做法是**流式生成 + 流式下发**,内存稳定 200 MB 以内,百万行不爆。

### A.2 强制规则

1. **必须使用 [server/utils/excelExport.js](../server/utils/excelExport.js) 提供的 `streamExportXlsx`** —— 禁止自己 `new ExcelJS.Workbook()`,禁止用 CSV 假装 xlsx
2. **数据源必须是迭代器** —— SQLite 用 `stmt.iterate(...)`,MySQL 用 `iterateByKeyset(...)` 或驱动原生 stream。**禁止 `stmt.all()`**
3. **必须 keyset 分页(`WHERE id > ?`),禁止 `LIMIT OFFSET` 翻大页** —— 偏移越大越慢,5 万行后明显劣化
4. **SQL 必须 `ORDER BY id ASC`**,且必须有覆盖索引,否则禁止上线
5. **禁止 `SELECT *`**,只取导出列定义里出现的字段

### A.3 实现模板(SQLite,当前阶段)

```javascript
const { streamExportXlsx } = require('../utils/excelExport')

router.post('/export', authMiddleware, async (req, res) => {
  const { scope, ids, filters, fields } = req.body

  // 第六章规定的字段白名单校验
  if (!Array.isArray(fields) || fields.length === 0) {
    return res.status(400).json({ code: 400, message: '请选择至少一个导出字段' })
  }

  // 按 scope 拼 WHERE
  const where = buildWhereByScope(scope, ids, filters, req.user)

  const sql = `
    SELECT id, ${safeFields(fields).join(', ')}
    FROM your_table
    WHERE ${where.sql}
    ORDER BY id ASC
  `
  const stmt = db.prepare(sql)

  // 审计日志(参见第十章)
  writeAuditLog(req.user.id, 'EXPORT_YOUR_RESOURCE', { scope, filters, fields })

  await streamExportXlsx({
    res,
    fileName: buildFileName(scope, filters),  // 第 5.6 节的命名规范
    sheetName: '数据',
    columns: buildColumnDefs(fields),         // 中文表头 + numFmt
    rows: stmt.iterate(...where.params),
  })
})
```

### A.5 SQL 与索引

**必须 ORDER BY 主键 ASC**:keyset 分页和流式迭代都依赖此。**不要用业务时间排序**(可能不唯一,会漏数据/重复)。

**时间范围必须命中索引**:

```sql
-- ✅ 命中 idx_xxx_date
WHERE work_date BETWEEN ? AND ?

-- ❌ 函数包裹索引失效
WHERE strftime('%Y-%m', work_date) = '2026-05'
WHERE DATE_FORMAT(work_date, '%Y-%m') = '2026-05'
```

**联合索引**按选择性从高到低,且包含导出列形成覆盖索引:

```sql
CREATE INDEX idx_wr_emp_date ON work_reports(employee_id, work_date, id);
```

### A.6 错误处理(关键)

**`streamExportXlsx` 一旦开始,响应头已发,就不能再 `res.json`**。所以:

- **参数校验必须在调用 `streamExportXlsx` 之前完成**
- 流式过程中抛错只能 `res.end()` 中断,前端会拿到一个不完整的下载
- 客户端中途断开,Node 会自动停止迭代,不会继续耗 CPU

```javascript
router.post('/export', async (req, res) => {
  try {
    if (!validate(req.body)) {
      return res.status(400).json({ code: 400, message: '...' })
    }
    await streamExportXlsx({ ... })
  } catch (err) {
    if (!res.headersSent) {
      res.status(500).json({ code: 500, message: '导出失败' })
    } else {
      console.error('[export] streaming error:', err)
      try { res.end() } catch (_) {}
    }
  }
})
```

### A.7 行数上限与异步通道

第 5.8 节给出的 20000 行上限是**保守值**。本仓库使用流式实现后,**单次同步导出可稳定支持 50 万行,1 分钟内完成**(前提是 SQL 走索引、字段不超过 30 列)。

工程化建议:

| 行数 | 方案 | SLA |
|------|------|-----|
| < 1 万 | 流式 xlsx 同步下载 | < 5 秒 |
| 1 万 ~ 10 万 | 流式 xlsx 同步下载 + 前端 loading | < 30 秒 |
| 10 万 ~ 50 万 | 流式 xlsx 同步下载 + 进度轮询 | < 1 分钟 |
| > 50 万 或 跨多 sheet | 异步任务通道(后台生成 + 通知下载) | 几分钟 ~ 几十分钟 |

### A.8 反例(请勿模仿)

#### 反例 1:全量加载 → OOM

```javascript
  rows.forEach(r => sheet.addRow(r))

}
```
